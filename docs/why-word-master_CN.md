# 为什么用 word-master —— 以及什么时候不该用

[English](./why-word-master.md) | 中文

## 一句话版本

当你需要文档**反复看起来就是从你们单位出来的**，而人工排版要耗掉几个小时——用它。当你只要一份格式无所谓的文档——别用。

## 把问题说准

AI 写东西已经解决了。排版没有。而时间恰恰耗在排版上——不是产出文档，而是产出**能过评审**的文档。

这是结构性问题，不是模型好坏问题：

| 根因 | 后果 |
|---|---|
| 模型没有样式真相源 | 每次运行都长出略微不同的样子 |
| 编号是文本不是域 | 插一章，后面全错 |
| 题注和交叉引用是文本 | 重编号＝全文手工搜索替换 |
| "用模板"是提示，不是约束 | 粘一段文字就静默断链 |

往提示词里加更多指令解决不了。你没法靠提示词得到确定性输出。你需要**契约**和**门禁**。

## word-master 到底改变了什么

三件事，每一件都是机械保证而不是口头承诺：

**1. 格式决定不由模型做。**
模型只输出语义角色（`h1`、`body`、`figure`）。builder 按 `contract.json` 把角色映射到 `styleId`。代码里不存在"模型设置字号"这条路径。

**2. 格式违规交付不出去。**
每次构建后跑 `doc_checker.py`，任何 `blocking` 都以非零码退出。门禁是 fail-closed：不认识的样式算失败，不是警告。

**3. 模板是单位自己的。**
`template_src.docx` 是你们单位真实在用的那份文档的字节副本。样式表不是重新生成的、不是近似的、不是"参考"的——就是同一份。

第 3 点是它和通用 "docx skill" 的根本区别。真正的资产是模板包，而模板包恰恰是最难复制的东西。

## 适合的场景

| 场景 | 契合度 |
|---|---|
| 工程可研、技术报告、评审文件 | **极佳**——参考模板就是为此而做 |
| 单位强制模板、固定样式表 | **极佳**——这正是 Create Template 路线 |
| 会合并成总册的文档 | **好**——7 级以下手打序号天然抗合并重排 |
| 交叉引用、图表编号密集的文档 | **好**——REF 域 + 自动编号题注 |
| 格式一致性会被评审的长文档 | **好**——门禁就是价值所在 |
| 有格式要求的方案、标书 | **好**——模板入库，正文生成 |

## 不适合的场景

这些边界是有意为之，不是等着被填的坑。

| 场景 | 为什么不适合 |
|---|---|
| 一次性通知、备忘、短函 | 配置成本超过收益。直接写。 |
| 宣传物料、画册、设计版式 | Word 就是错工具，契约模型也和自由排版打架 |
| 依赖浮动图片、文本框、内容控件的模板 | 当前 builder 无法完全复现，入库分析会标出来 |
| 需要自动生成封面和签署栏 | 有意留给人工。单位差异太大，做错比留空更糟 |
| 想要一个托管 Web 应用 | 这是本地 skill，设计如此——文档不出你的机器 |
| 交付物主要是 PDF | DOCX 才是交付物，PDF 是 Word/WPS 导出的结果 |
| 你的"模板"其实只是视觉风格，不是样式表 | 没有东西可以锁。先做一份真模板。 |

## 和其他方案的对比

**直接让通用模型"写一份 Word"**
一次性任务能用。每次都不一样。没有任何东西强制单位样式表。重排一次的成本超过写作本身。

**Jinja2 / docxtpl**
填固定文档的占位符很强。但它没有**文档结构**概念：没有标题层级、没有自动编号、没有题注配对、没有交叉引用域、没有门禁。当你的文档是**表单**而不是**报告**时，用它。

**Markdown → Pandoc**
产出一套干净、通用的样式表。单位模板被丢弃，而且没有门禁告诉你输出漂移了。适合发布流水线，不适合组织文档。

**在 Word 里手工做**
输出正确，成本线性增长——而那份成本正是 word-master 要消掉的。

## 诚实的局限

- **文笔是模型的事。** 门禁保证格式，不保证第 3 章和第 1 章不矛盾。
- **门禁的上限是契约。** 契约推导错了，门禁会忠实地执行错的东西。这就是 *Create Template* 必须有阻塞评审步骤的原因。
- **一个模板包对应一套模板。** 单位有五套强制模板就要五个包。这是有意的——每个包自带审计线索。
- **参考模板固化了某一家单位的约定**（七级标题、7 级以下手打序号、表题在上）。你们单位不一样，就写你们自己的规则——不要去改 checker。

## 什么样算成功

评审在**读内容**，而不是在**看格式**。如果评审意见全是关于你写了什么、没有一条是关于它长什么样——这个工具就干成了它该干的事。
