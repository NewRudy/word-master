# AI 写的 Word，为什么每次格式都不一样

> 这篇文章讲一个具体问题：**为什么 AI 能写正文，却始终做不出一份能过评审的 Word**。
> 文末是一个开源工具，以及它为什么这样设计。
>
> 如果你不写工程报告、可研、标书、验收文档，这篇文章对你用处不大。

---

## 一个所有人都遇到过的场景

你让 AI 写一份可行性研究报告。它写得不错：结构完整、逻辑通顺、措辞也像那么回事。

然后你把文档交给评审。

评审翻了两页，抬头说："格式重排一下。"

你打开文档，发现问题不是一处：

- 一级标题 16pt，二级 15pt，三级又跳回 14pt，但第四章的三级是 12pt
- 章节编号是手打的 `1.1`、`1.2`，你插入一章之后，后面全错
- 图 3 的图名在图**上面**，图 5 的图名在图**下面**
- 表 2 是三线表，表 4 是全框线表
- 正文里写"详见表 3-2"，但那张表实际编号是"表 2.1-1"

你花了一整天手工修。修完你意识到：**下次还得再来一遍。**

---

## 这不是模型不够聪明

很多人第一反应是"换个更强的模型"。没用。

问题的根源不在生成质量，在于**结构**：

| 根因 | 后果 |
|---|---|
| 模型没有样式真相源 | 每次运行都长出略微不同的样子 |
| 编号是文本不是域 | 插一章，后面全错 |
| 题注和交叉引用是文本 | 重编号＝全文手工搜索替换 |
| "用模板"是提示，不是约束 | 粘一段文字就静默断链 |

第四条最关键。你在提示词里写"请使用单位模板的样式"，模型会**尽力**遵守。但"尽力"不是"保证"。它可能在第 8 段忘了，可能把 `正文格式` 和 `Normal` 搞混，可能在你不注意的时候给某个段落加了 12pt 的直接字号。

而格式这种东西，**一处错就等于全错**——评审不会因为 99% 的段落对就放过那 1%。

**你没法靠提示词得到确定性输出。** 这不是提示词工程能解决的问题，是架构问题。

---

## 换个思路：把"格式决定"从模型手里拿走

既然模型做格式决定会漂移，那就**不让它做**。

具体做法是把一份文档拆成两层：

```
内容层（AI 写）        格式层（契约决定）
─────────────────      ─────────────────
# 概述                  → 样式 "heading 1"（黑体 16pt，自动编号 1.）
正文段落……              → 样式 "正文格式"（宋体 12pt，首行缩进 2 字符）
:::figure location     → 样式 "图片格式"（居中，嵌入型）
:::caption fig ...     → 样式 "图名格式"（黑体 12pt，自动编号 图1.1-1）
| 表头 | 表头 |        → 样式 "Table Grid" + "表格文字"
```

AI 只输出左边那一列——**语义角色**，不带任何格式信息。右边那一列由一份 `contract.json` 决定，而这份契约是从**你们单位真实在用的模板**里推导出来的。

然后加一道门禁：

```bash
$ doc_checker.py check 我的报告

BLOCKING [C1] 样式不在契约白名单: styleId=30        @body#47
BLOCKING [C4] 题注疑似手打编号: '图1.1-1 某河道...'  @body#52
BLOCKING [C6] 图片段之后不是图名                     @body#55
=> FAIL  blocking=3 advisory=0
```

**blocking 不清零，不许交付。**

这不是建议，是硬性退出码。

---

## 三个机械保证

到这里，"不漂移"就从愿望变成了三个可验证的性质：

### 1. 格式决定不由模型做

模型输出 `h1`，builder 按契约把 `h1` 映射到 `styleId=2`。代码里**不存在**"模型设置字号"这条路径——不是"不推荐"，是没有这个函数。

### 2. 违规交付不出去

每次构建后跑门禁。不认识的样式算**失败**，不是警告。这是 fail-closed 设计：宁可拦下一个正常文档，也不放过一个格式错位。

### 3. 模板是单位自己的

`template_src.docx` 是你们单位那份文档的**字节副本**。样式表不是重新生成的、不是近似的、不是"参考"的——就是同一份。

第 3 点是这件事和"通用 docx 提示词"的根本区别。**真正的资产是模板包，而模板包恰恰是最难复制的东西。**

---

## 为什么这件事值得做

因为痛点是真的，而且算得清账。

我自己最近做了一份 Web 端 GIS+BIM 平台的用户手册。规模不算小：

| 项 | 数量 |
|---|---|
| 字数 | 约 1.8 万字 |
| 段落 | 602 段 |
| 插图 | 47 张 |
| 表格 | 11 张 |

**以前人工做，从搭结构、写内容、截图、排版到改三轮，起码两天。**

这次从给材料到交出可评审的成稿，**不到半小时**。

省下来的不是"写字的时间"——字还是要想的。省下来的是：47 张图的题注编号、11 张表的表题、602 个段落的首行缩进和行距、全文几十处"见图 x.x-x"的交叉引用，以及三轮修改后重新编号的返工。

这些工作没有一分钟在产生价值。而且**人工做 47 张图的编号，出错是必然的**——不是会不会错的问题，是错几处的问题。

## 工具：word-master

我把上面这套东西做成了开源工具：

**https://github.com/NewRudy/word-master**

形态上和 [ppt-master](https://github.com/hugohe3/ppt-master) 同源——一套在有 Agent 能力的 AI 工具里运行的"skill"。你在 Claude Code / Cursor / Codex / pi 里打开这个目录，说"用这份材料写一份可研报告"，它就跑完整条流水线。

![同一份内容，两种产出](assets/before-after.png)

### 它做什么

```
主题/材料 ──▶ 事实研究(facts.json 溯源) ──▶ 建项目+导入
         ──▶ ⛔ 确认模板与大纲（不会自作主张往下走）
         ──▶ AI 写 content.md（纯语义，不碰格式）
         ──▶ 注入模板壳
         ──▶ 质量门禁（fail-closed）
         ──▶ 交付（WPS 里 Ctrl+A → F9 刷域）
```

三条路线：

- **生成报告**：主题/材料 → 带溯源的报告
- **模板入库**：把单位的 `.docx` 变成可复用的模板包
- **改已有文档**：定点修改，其余部分字节保留

### 内置四个模板

| 包名 | 适用场景 | 正文 | 最深标题 |
|---|---|---|---|
| `qiji_heading` | 工程技术报告（参考实现） | 宋体 小四 | 7 级 |
| `gov_report` | 政府机关公文 / 技术报告 | 仿宋 小四 | 5 级 |
| `acceptance_report` | 验收 / 评审报告 | 宋体 小四 | 5 级 |
| `meeting_minutes` | 会议纪要 / 工作简报 | 宋体 小四 | 3 级 |

后三个是从第一个**派生**的：共用同一份单位原件和编号体系，只覆盖正文字体和标题深度。派生工具会校验产出的 OOXML（每个 part 可解析、能打开、契约角色都指向真实样式），校验不过就报错——手写 `styles.xml` 是拿到一个 Word 打不开的模板的最快方式。

### 门禁管什么

十条规则，都是我在真实文档上踩过的：

| 规则 | 内容 | 级别 |
|---|---|---|
| C1 | 段落样式必须在契约白名单内 | blocking |
| C2 | 中文字体只许宋体/黑体（或契约允许的），西文只许 TNR | blocking |
| C3 | run 级直接格式只许加粗/斜体/上下标，禁改字号颜色 | blocking |
| C4 | 标题/题注编号必须来自自动编号域，手打前缀即拦 | blocking |
| C5 | 7 级以下序号必须手打（单位约定，跨文档合并不串号） | blocking |
| C6 | 图名在图下、表题在表上，且必须成对 | blocking |
| C7 | 表格样式与单元格样式必须符合契约 | blocking |
| C8 | 连续空段落 | advisory |
| C9 | "见 3.2 节"与实际编号不一致 | advisory |
| C10 | 正文首行缩进被覆盖 | advisory |

---

## 诚实的部分

**文笔是模型的事。** 门禁保证格式，不保证第 3 章和第 1 章不矛盾。

**门禁的上限是契约。** 契约推导错了，门禁会忠实地执行错的东西。所以模板入库有一个强制的阻塞评审步骤。

**一个模板包对应一套模板。** 单位有五套强制模板就要五个包。这是有意的——每个包自带审计线索（`template_src.docx` 永不被修改）。

**封面和签署页不做。** 单位差异太大，做错比留空更糟。

**不适合的场景**：一次性通知、宣传物料、依赖浮动图片/文本框的模板、以及"你的模板其实只是视觉风格不是样式表"的情况——没有东西可以锁。

## 最后

这个工具解决的不是"AI 会不会写文档"，而是"AI 写的文档能不能直接用"。

这两件事之间隔着的东西，比大多数人以为的多。它不是一个提示词能填的坑，是一层结构。

如果你的工作里有"格式被退回重排"这件事，欢迎试试，也欢迎告诉我你们单位的模板长什么样——那正是这个项目最需要的东西。
